# Передача реализации дашборда для другого ИИ

Дата документа: 09.07.2026 09:15 MSK

Этот документ описывает, что было реализовано в проекте Excel-дашборда, как устроены расчеты и какие места кода нужно переносить или учитывать другой ИИ при внедрении аналогичной логики.

Основная история решений находится в `История_переписки.md`. Этот файл является выжимкой для внедрения: не переписка, а техническое описание текущего состояния.

## 1. Контекст проекта

Проект находится в папке:

```text
/Users/ermolaevatatana/Documents/Дашборд - отчет по Excel
```

Основные файлы:

- `index.php` - HTML-разметка дашборда и контейнеры вкладок.
- `script.js` - вся логика загрузки Excel, расчетов, агрегаций, фильтров и рендера.
- `style.css` - визуальные стили блоков, фильтров, шкал, таблиц и адаптива.
- `Dashboard_report_Technical_unit.xlsm` - исходная Excel-книга.
- `История_переписки.md` - журнал всех решений и действий.
- `Передача_реализации_для_ИИ.md` - текущий файл передачи.

Технологически дашборд работает в браузере и читает Excel через `XLSX`. Данные не хранятся в базе, а собираются из листов Excel при загрузке файла.

## 2. Главные пользовательские решения

Были приняты и реализованы такие решения:

- убрать блок `Проектная структура загрузки по центрам`;
- убрать блок `Проекты вне плана`;
- убрать старый блок `Проекты` со вкладки `ТехБлок`;
- добавить вкладку `ПП` с расшифровкой `Производственная программа`;
- перенести блок `План-факт по проектам` на вкладку `ПП`;
- переместить вкладку `ПП` в самый конец навигации;
- убрать вкладку `Расчеты` из навигации;
- перенести `Динамика загрузки по кварталам` на вкладку `ТехБлок`;
- считать квартальную динамику по плоским таблицам;
- на вкладках центров вместо `Общая загрузка по месяцам` показывать `Динамика загрузки по кварталам`;
- ограничивать отображаемый процент квартальной динамики максимумом `100%`;
- для вкладки `ПП` по умолчанию скрывать факт и показывать план;
- на всех остальных вкладках факт показывать по умолчанию;
- добавить единый чекбокс `Факт` в панель фильтров `ПП`;
- добавить фильтры интерфейсной вкладки `ПП` по полям из листа Excel `ПП`;
- использовать новый формат листа Excel `ПП` вместо старого `План_продаж`;
- использовать столбец `Месяц` на листе `ПП` для месячного распределения часов;
- ускорить переключение вкладок на реальном Excel-файле через кэширование и ленивый рендер тяжелых строк;
- на вкладке `ТехБлок` вернуть новую таблицу проектов, но строить ее из `Проекты_ТехБлок`;
- для таблицы проектов добавить режимы `По центрам / По задачам`, фильтр `Все задачи / Задачи УПЦ` и фильтр просрочек;
- добавить скрытый блок `Задачи для проверки`;
- исключать из таблицы проектов и диагностики строки со статусом `Отменена` и статусы вне матрицы, например `Потенциальная`;
- добавить блок `Целевой показатель` под уведомлениями по проектам;
- на `ТехБлок` в заголовке блока загрузки писать `Загрузка блока`, на центрах оставлять `Загрузка центра`;
- в целевом показателе в карточке `В норме часов` показывать сумму превышения часов.

## 4. Режимы отображения

Переключение вкладок идет через `loadSheetData(sheetName)`.

Для `ПП` логика отдельная:

```js
if (sheetName === 'ПП') {
    chartManager.destroyAll();
    currentSheet = sheetName;
    worksheetCache = getCachedWorksheetCache('ТехБлок');
    switchToProductionProgramMode();
    activateNavButton(sheetName);
    updateFileInfo();
    resolve();
    return;
}
```

То есть:

- `currentSheet` становится `ПП`;
- для технических общих данных используется кэш листа `ТехБлок`;
- основной экран дашборда скрывается;
- показывается `production-program-content`;
- вызывается `renderProductionProgramPlanFact()`.

Для обычных вкладок центров вызывается `switchToMainMode()` и затем `renderAll()`. В `renderAll()` сейчас рендерятся:

- шапка;
- уведомления;
- карточки загрузки;
- табель;
- для вкладок центров - квартальная динамика вместо месячной загрузки;
- для `ТехБлок` - блок загрузки с заголовком `Загрузка блока`;
- блок `Динамика загрузки по кварталам`;
- блок `Целевой показатель`;
- таблица `Проекты`;
- остальные актуальные блоки центра.

## 5. Используемые листы Excel

### `ПП`

Это лист Excel с производственной программой / планом продаж. Не путать с интерфейсной вкладкой `ПП`: вкладка интерфейса собирает и визуализирует данные, а лист Excel `ПП` является источником плановых строк.

Актуальная структура листа идет по порядку с первого столбца:

```text
Бизнес-направление
Статус проекта
Заказчик
Наименование проекта
Номер сделки из Битрикс24
Номер задачи
Заказ клиента: номер и дата (указывается при наличии)
Тип работ
Ответственный от Бизнес-направления
Руководитель проекта
Дата начала проекта
Дата окончания проекта
Уровень реализации проекта
Планируемое участие
План-продаж, в тыс. руб.
Место возникновения затрат (МВЗ)
Наименование конструкторского бюро
Управление
Месяц
Часы
Итого за 2025 год
Комментарий (предмет сделки)
```

Роли колонок:

- `Номер задачи` - ID проекта, связывает план продаж с проектами и загрузкой.
- `Бизнес-направление` - фильтр на вкладке `ПП`.
- `Статус проекта` - фильтр на вкладке `ПП`.
- `Заказчик`, `Номер сделки из Битрикс24`, `Заказ клиента`, `Тип работ`, `Ответственный`, `Руководитель проекта`, `Уровень реализации проекта`, `Планируемое участие`, `План-продаж`, `Комментарий` - справочные поля, сейчас не являются ключевыми расчетными полями.
- `Наименование проекта` - имя проекта, если строки нет в `Проекты_ТехБлок`.
- `Дата начала проекта` - плановая дата начала.
- `Дата окончания проекта` - плановая дата окончания.
- `Место возникновения затрат (МВЗ)` - фильтр на вкладке `ПП`.
- `Наименование конструкторского бюро` - фильтр на вкладке `ПП`.
- `Управление` - связь с центром или управлением; в одном столбце могут быть и центры, и управления.
- `Месяц` - месяц, на который относятся часы.
- `Часы` - плановые часы за месяц.

Логика чтения находится в `getTechBlockSalesPlanByProject(managementCenterLookup)`.

Имя листа определяется функцией `getSalesPlanWorksheetName()`:

```js
['ПП', 'План_продаж', 'План-продаж']
```

Приоритетный источник сейчас - `ПП`. Старые имена оставлены как fallback для совместимости.

Поддерживаются старые алиасы для некоторых колонок:

- `ID` как резерв для `Номер задачи`;
- `Итого за 2026 год`, `Плановые часы`, `Количество ПЛАНовых часов` как резерв для `Часы`;
- `Месяц плана`, `Месяц загрузки` как резерв для `Месяц`;
- `Место возникновения затрат`, `МВЗ` как резерв для `Место возникновения затрат (МВЗ)`;
- `Конструкторское бюро` как резерв для `Наименование конструкторского бюро`.

### `Проекты_ТехБлок`

Используется как основной справочник проектов, центров, управлений, статусов, плановых и фактических дат по этапам.

Важные поля:

- `ID`;
- `Наименование проекта` или `Проект`;
- `Центр`;
- `Управление`;
- `Статус`;
- `Количество ПЛАНовых часов` или `Плановые часы`;
- `Количество ФАКТических часов` или `Фактические часы`;
- плановые, фактические и прогнозные даты.

Если проект есть в листе Excel `ПП`, плановые часы и даты берутся из `ПП`. Если проекта нет в `ПП`, он может быть использован как проект вне плана в расчетах, где это допустимо.

### `Загрузка_ТехБлок`

Используется для факта и прогноза по проектам.

Важные поля:

- `ID` - ID проекта;
- `Дата`;
- `ФИО`;
- `Часы`;
- `Центр`;
- `Управление`;
- `Прогноз`;
- `Отсутствия`;
- `Табель`;
- `Административный персонал`;
- `Дата увольнения`.

Правила:

- факт берется из строк без прогноза;
- прогноз берется из строк, где поле `Прогноз` заполнено / не равно `0`;
- отсутствие определяется полем `Отсутствия`;
- значение `к` в `Отсутствия` не считается отсутствием;
- административный персонал исключается;
- сотрудник исключается после даты увольнения;
- для отсутствий используется `Табель`, если поле есть, иначе fallback к часам строки.

### `Сотрудники_ТехБлок`

Используется для справочника сотрудников и фонда часов.

Важные поля:

- `ФИО`;
- `Центр`;
- `Управление`;
- `Дата выхода`;
- `Дата увольнения`;
- `Ставка`;
- `Административный персонал`.

Правила:

- сотрудник относится к одному центру;
- административный персонал не входит в производственный фонд;
- ставка умножается на часы рабочего дня;
- дата выхода и дата увольнения ограничивают период участия сотрудника в фонде часов.

### `Табель`

Используется как календарь рабочих дней и часов.

Важные поля:

- `Дата`;
- `Часы`.

Для фонда часов берутся только строки, где есть дата и `Часы > 0`.

## 6. Связь плана продаж с проектами и центрами

Связь строится не только по ID проекта, но и по названию управления или центра.

Основной ID:

```text
ПП[Номер задачи] -> Проекты_ТехБлок[ID] -> Загрузка_ТехБлок[ID]
```

Связь центра:

```text
ПП[Управление] -> центр
```

Алгоритм:

1. Если в `Управление` указано название центра или короткий код центра, центр определяется напрямую.
2. Если указано управление, центр ищется через пары `Центр` + `Управление` из `Проекты_ТехБлок`.
3. Если в проектах связи нет, lookup дополняется из `Сотрудники_ТехБлок`.

Функции:

- `getTechBlockManagementCenterLookup(projectRows)`;
- `getTechBlockSalesPlanByProject(managementCenterLookup)`;
- `getSalesPlanCenterFromRow(row, managementCenterLookup)`;
- `resolveSalesPlanCenterValue(value, managementCenterLookup)`;
- `normalizeProjectCenterLabel(value)`;
- `normalizeManagementLabel(value)`.

## 7. Сбор план-факта проектов

Главная функция:

```js
getTechBlockProjectPlanFactDataFromTables()
```

Она делает следующее:

1. Читает строки `Проекты_ТехБлок`.
2. Загружает lookup сотрудников через `getTechBlockEmployeeLookup()`.
3. Считает факт и прогноз по проектам через `getTechBlockLoadByProject(employeeLookup)`.
4. Читает табель через `getTechBlockTimesheetCalendar()`.
5. Строит связь управления с центром через `getTechBlockManagementCenterLookup(projectRows)`.
6. Читает план продаж / производственную программу через `getTechBlockSalesPlanByProject(managementCenterLookup)`.
7. Группирует проекты по ID.
8. Добавляет плановые проекты из листа `ПП`, если их нет в `Проекты_ТехБлок`.
9. Для каждого проекта собирает:
   - статус;
   - этапы по центрам;
   - плановые часы;
   - фактические часы;
   - плановые часы по центрам;
   - плановые часы по центрам и месяцам;
   - факт по центрам и месяцам;
   - прогноз по центрам и месяцам;
   - плановые и фактические даты;
   - поля фильтров из листа `ПП`.
10. Фильтрует завершенные и отмененные проекты там, где они не должны участвовать.
11. Кэширует результат в `workbookDataCache.projectPlanFact`.

Если проект есть в листе `ПП`, то:

- `planHours` берется из `ПП`;
- `planHoursByCenter` берется из `ПП`;
- `planHoursByCenterMonth` берется из `ПП[Месяц] + ПП[Часы]`;
- факт берется из `Загрузка_ТехБлок`.

Если проекта нет в `ПП`, используется fallback из `Проекты_ТехБлок` и `Загрузка_ТехБлок`.

## 8. Месячное распределение плановых часов

Раньше план мог распределяться по периоду проекта равномерно. Теперь для проектов из листа `ПП` месячная плановая загрузка должна идти по столбцу `Месяц`.

Ключевые функции:

- `getSalesPlanMonthKey(row, planStart, planEnd)`;
- `parseSalesPlanMonthDate(value, planStart, planEnd)`;
- `getSalesPlanMonthFallbackYear(planStart, planEnd)`;
- `getSalesPlanMonthHoursByCenterForProject(planHoursByCenter, planHoursByMonth)`;
- `getPlanProjectHoursByMonth(projects)`.

Правило:

```text
Плановая загрузка месяца = сумма ПП[Часы] по этому ID, центру и месяцу.
```

Если месяц не удалось прочитать, используется fallback-логика по датам проекта.

## 9. Расчет фактических часов

Главная функция:

```js
getTechBlockLoadByProject(employeeLookup)
```

Для каждой строки `Загрузка_ТехБлок`:

- определяется `ID`;
- читаются `Часы`, `Дата`, `ФИО`;
- сотрудник связывается с `Сотрудники_ТехБлок`;
- проверяется административный персонал;
- проверяется дата увольнения;
- проверяется отсутствие;
- проверяется прогноз;
- определяется центр и управление.

Строка попадает в факт, если:

```text
не административный персонал
и сотрудник активен на дату строки
и строка не является отсутствием
и строка не является прогнозом
```

Факт агрегируется в:

- `entry.actualHours`;
- `entry.centerHours`;
- `entry.centerMonthHours`;
- `entry.workUnitHours`.

Прогноз агрегируется отдельно в:

- `entry.forecastHours`;
- `entry.forecastCenterMonthHours`.

Отсутствия агрегируются отдельно в:

- `entry.absenceHours`.

## 10. Расчет фонда часов

Главная функция:

```js
getTechBlockCenterCapacityByMonth(monthIntervals)
```

Формула:

```text
Доступный фонд центра за месяц =
    сумма(Табель[Часы] * Сотрудники_ТехБлок[Ставка])
    по всем неадминистративным активным сотрудникам центра
    минус часы отсутствий
```

Правила:

- рабочие дни и часы берутся из `Табель`;
- сотрудники берутся из `Сотрудники_ТехБлок`;
- административный персонал исключается;
- сотрудник учитывается только между `Дата выхода` и `Дата увольнения`;
- ставка по умолчанию равна `1`, если поле пустое;
- отсутствия берутся из `Загрузка_ТехБлок`;
- для отсутствий используется `Табель` из строки загрузки, затем умножается на ставку;
- итоговый фонд не может быть меньше нуля.

Результат:

```js
Map<center, Map<monthKey, {
    grossHours,
    absenceHours,
    availableHours
}>>
```

## 11. Блок `Общая загрузка по месяцам` на вкладке `ПП`

Этот блок находится внутри `План-факт по проектам` на вкладке `ПП`.

Главная функция:

```js
renderPlanFactHeatmapSummary(projects, startDate, endDate)
```

Правила:

- для планового ряда берутся только проекты из листа `ПП`;
- `plannedProjects = projects.filter(project => project.isPlanned)`;
- факт берется только по активным проектам из плана продаж;
- `activeProjects = plannedProjects.filter(project => project.status.type === 'active')`;
- фонд часов берется из плоских таблиц через `getCenterMonthlyLoadMonthsForRange(startDate, endDate)`;
- плановые часы по месяцам берутся из `getPlanProjectHoursByMonth(plannedProjects)`;
- факт по месяцам берется из `getActiveProjectActualHoursByMonth(activeProjects)`.

Формула процента:

```text
% факт / в работе = round(фактические часы активных плановых проектов / фонд часов * 100)
% план = round(плановые часы из ПП / фонд часов * 100)
```

В коде универсальная функция:

```js
getMonthlyProjectLoadRows(months, workHoursByMonth, forecastHoursByMonth, options)
```

Она возвращает:

- `workHours`;
- `forecastHours`;
- `workPercent`;
- `forecastPercent`.

Для `ПП` параметр `forecastHoursByMonth` фактически используется как плановый ряд, а не как прогноз. Поэтому в рендере передается `{ forecastLabel: 'план' }`.

Факт на `ПП` по умолчанию скрыт. Пользователь видит план.

## 12. Квартальная динамика на вкладках центров

На вкладках центров (`ЦНГО`, `ЦДЦМ`, `ЦДПМ`, `ЦОТ`, `УВП`, `ЛОИ`) блок `Общая загрузка по месяцам` убран. На его месте выводится `Динамика загрузки по кварталам`.

Рендер запускается через:

```js
renderCenterMonthlyLoadSection()
```

Фактические квартальные данные центра собираются так:

- центр определяется из текущей вкладки через `normalizeProjectCenterLabel(currentSheet)`;
- месячные фактические часы берутся из `Загрузка_ТехБлок` через `getSpentProjectHoursByMonthForCenter(centerKey)`;
- фонд часов по центру берется из `getTechBlockCenterCapacityByMonth(monthIntervals)`;
- месяцы группируются в кварталы через `buildQuarterlyTrendData(months)`;
- показываются последние 4 квартала через `getQuarterlyTrendDisplayQuarters()`.

Формула:

```text
% квартала центра = сумма фактических часов центра / сумма доступного фонда центра * 100
```

Если последний отображаемый квартал относится к текущему/будущему периоду и падает ниже предыдущего из-за неполных будущих данных, точка удерживается на уровне предыдущего квартала (`holdLastFutureDrop`).

Если квартальных данных нет, верхний контейнер очищается и скрывается, пустая заглушка не выводится.

## 13. Квартальная динамика

Блок `Динамика загрузки по кварталам` есть на вкладке `ТехБлок` и на вкладках центров.

Для `ТехБлок` данные считаются по плоским таблицам:

```js
getTechBlockQuarterlyTrendDataFromTables()
```

Расчет:

- факт по месяцам берется из `Загрузка_ТехБлок` через `getTechBlockActualHoursByMonthFromLoadTable()`;
- фонд часов по центрам и месяцам берется через `getTechBlockCenterCapacityByMonth(monthIntervals)`;
- фонд всех центров суммируется по месяцу;
- месяцы группируются в кварталы через `buildQuarterlyTrendData(months)`.

Формула:

```text
% квартала = сумма фактических часов за доступные месяцы квартала / сумма доступного фонда часов за эти месяцы * 100
```

Отображаемый процент квартальной загрузки ограничен максимумом `100%`:

```js
clampQuarterlyTrendPercentage(value)
```

То есть если расчет дает больше `100%`, на графике и в бейдже показывается `100%`. Часы `loadHours` и `totalHours` при этом не меняются.

Факт исключает:

- прогноз;
- отсутствия;
- административный персонал;
- сотрудников после даты увольнения.

## 14. Блок `Целевой показатель`

Блок находится под `Уведомления по проектам` и рендерится функциями:

```js
updateTargetIndicator()
getTargetIndicatorData()
renderTargetIndicatorContent(data)
```

Источник данных - лист `Проекты_ТехБлок`.

Используемые поля:

- `Центр`;
- `ID`;
- `Вид проекта`;
- `Статус`;
- `План дата завершения этапа по графику проекта` / старые алиасы плановой даты;
- `Количество ПЛАНовых часов` / `Плановые часы`;
- `Количество ФАКТических часов` / `Фактические часы`;
- `ФАКТ начало`;
- `ФАКТ окончание`;
- `Статус КД` / `Статус РКД` / `КД` / `Столбец 17`.

Учитываются только коммерческие и инвестиционные проекты:

```js
TARGET_INDICATOR_ALLOWED_PROJECT_TYPES
```

Периоды:

- `I полугодие 2026`;
- `II полугодие 2026` появляется после 01.07.2026.

Фильтр включения:

- задача должна начаться фактически в выбранном полугодии;
- задача должна быть коммерческой или инвестиционной;
- для центров КБ нужен хотя бы один статус КД `Готово`;
- для `ЛОИ` статуса КД нет, поэтому берется статус проекта `Завершена`;
- `УВП` исключен из целевого показателя полностью.

На вкладке `ТехБлок` группы целевого показателя:

- `Центры КБ` - все центры кроме `ЛОИ` и `УВП`;
- `ЛОИ` - отдельно.

На вкладках конкретных центров показывается только соответствующий центр. Для `УВП` блок не отображается.

Формулы:

```text
В срок % = задачи, где ФАКТ окончание <= План дата завершения этапа / завершенные задачи * 100
В норме часов % = задачи, где ФАКТ часы <= ПЛАН часы / завершенные задачи * 100
```

Для карточки `В норме часов` дополнительно показывается сумма превышения часов:

```text
превышение = сумма max(0, ФАКТ часы - ПЛАН часы)
```

Считается только по завершенным задачам выбранного среза.

В блоке есть скрытый `details` со списком `ID задач в расчете`.

Ключевые функции:

- `getTargetIndicatorAvailablePeriods()`;
- `getTargetIndicatorProjectRecords()`;
- `isTargetIndicatorProjectStartedInPeriod()`;
- `isTargetIndicatorProjectCompletedInPeriod()`;
- `isTargetIndicatorProjectInHours()`;
- `getTargetIndicatorProjectHoursOverrun()`;
- `getTargetIndicatorDisplayGroup()`;
- `renderTargetIndicatorTaskIds()`;
- `renderTargetIndicatorMetric()`.

## 15. Таблица `Проекты`

Таблица проектов снова выводится на `ТехБлок` и на вкладках центров, но данные берутся не из диапазонов листов центров, а из плоского листа `Проекты_ТехБлок`.

Ключевые функции:

- `updateProjects()`;
- `getProjectsFromDetails()`;
- `getProjectsFromTechBlockForCenter(centerKey, options)`;
- `renderProjectsControls()`;
- `renderProjectDetails(projects, status, type)`;
- `renderProjectTableDiagnostics(diagnostics)`.

Статусы общей матрицы:

```text
В работе
На паузе
В очереди
У заказчика
Завершена
```

Строки со статусом `Отменена` / `Отменен` / `Отменено` игнорируются полностью. Строки со статусами вне матрицы, например `Потенциальная`, тоже игнорируются и не попадают в `Задачи для проверки`.

Группировка:

- на вкладках центров основной режим называется `По управлениям`;
- на вкладке `ТехБлок` основной режим называется `По центрам`;
- режим `По задачам` объединяет записи задачи по датам и часам;
- счетчик ячеек матрицы всегда считает уникальные задачи по `центр + ID`, чтобы не меняться от режима отображения.

Для `ТехБлок` в режиме `По центрам` задачи группируются по центрам, над списком выводится полное название центра, столбец `Центр` не выводится. В режиме `По задачам` задачи объединяются без разбивки, а столбец `Центр` выводится краткими кодами центров.

Фильтры:

- `Все задачи / Задачи УПЦ`;
- `Все сроки`;
- `Просрочка даты`;
- `Просрочка часов`;
- `Дата или часы`.

Фильтр `Дата или часы` работает по логике `или`: показываются задачи с просрочкой по дате или по часам.

Блок `Задачи для проверки` скрыт по умолчанию. В него выводятся только реальные неоднозначности, например несколько видов проекта у одного `центр + ID` или строки без центра/ID. Не выводятся:

- отличающиеся статусы, потому что статус выбирается по приоритету;
- отмененные строки;
- статусы вне матрицы;
- служебные ID `1001`, `1002`, `-`, если у них не заполнены статус и вид проекта.

## 24. Известный нюанс текущего состояния

На вкладке `ПП` фонд часов для месячной загрузки считается по плоским таблицам:

Интерфейсная вкладка `ПП` и лист Excel `ПП` имеют одинаковое имя, но это разные сущности:

- лист Excel `ПП` - источник плановых строк, который читается через `getSalesPlanWorksheetName()`.
